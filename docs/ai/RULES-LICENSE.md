# Правила работы над лицензией

## Порядок
- Промпты 1–9 — строго по порядку.
- Промпт 1 (аудит) — обязателен до любых изменений.
- Промпт 6 (проверка) — обязателен до отчёта.

## Что НЕ трогать
- node_modules/
- package-lock.json (кроме поля license самого пакета)
- dist/
- .git/
- Лицензии сторонних библиотек в их собственных файлах
- Поле license у зависимостей в package.json

## Что менять
- Только свой код в src/
- Только свои конфиги в корне
- README.md, LICENSE
- package.json — только поля "license", "private", "author"

## Плейсхолдеры
- <ВЛАДЕЛЕЦ> — не заменять, оставить для ручного ввода.
- Qwen НЕ должен сам придумывать имя владельца.

## Коммиты
- Один промпт = один коммит.
- Формат: `chore(license): <описание> (#<номер>)`
- Примеры:
  - `chore(license): аудит MIT-вхождений (#1)`
  - `chore(license): удаление MIT-заголовков из src (#2)`
  - `chore(license): замена LICENSE на проприетарный (#3)`
  - `chore(license): package.json → UNLICENSED (#4)`
  - `chore(license): README без MIT (#5)`
  - `chore(license): финальная проверка (#6)`
  - `chore(license): правило для будущих файлов (#7)`
  - `chore(license): скрипт проверки (#8)`
  - `docs(license): отчёт о миграции (#9)`

## Когда останавливаться
- Если найдены MIT-заголовки в чужом коде — уточнить, не удалять.
- Если найден GPL/Apache-заголовок в нашем коде — уточнить (это может быть опасно для проприетарного продукта).
- Если после удаления заголовка файл ломается — откатить, разобраться.
